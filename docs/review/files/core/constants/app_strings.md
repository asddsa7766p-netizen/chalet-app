### lib/core/constants/app_strings.dart

- **الوظيفة:** class ثابت `AppStrings` يجمّع كل النصوص الظاهرة للمستخدم (onboarding، auth، home، تفاصيل الشاليه، الحجز، المفضلة، البروفايل، الإعدادات، التنقل، التقييمات، الإشعارات، رسائل التحقق) في مكان واحد، بالإضافة إلى قائمة `cities` الثابتة للمدن الفلسطينية.

- **الشرح التفصيلي:** كل الأعضاء `static const String` أو `static const List<String>` — لا يوجد أي منطق. `cities` قائمة نصوص عربية بالضبط: `['الكل', 'رام الله', 'نابلس', 'جنين', 'الخليل', 'بيت لحم', 'طولكرم', 'قلقيلية', 'أريحا']` تُستخدم على الأرجح كفلاتر بشاشات البحث/الرئيسية.

- **الاعتماديات:** لا يستورد شيئاً. **من يستخدمه:** شاشات متعددة لعرض نصوص عربية ثابتة (سيُؤكَّد اسم كل مستهلك أثناء مراجعة الشاشات).

- **التعامل مع Supabase:** لا يوجد.

- **نقاط القوة:** تجميع النصوص بمكان واحد أفضل من نصوص متناثرة داخل كل شاشة، ويسهّل تعديل الصياغة لاحقاً من نقطة واحدة.

- **الأخطاء والمخاطر المحتملة:**
  - 🟠 **متوسطة — لا يوجد دعم فعلي للغة الإنجليزية رغم إعلان التطبيق عنها:** [main.dart](../../main.md) يصرّح `supportedLocales: [Locale('ar'), Locale('en')]` ويحتوي التطبيق على `localeNotifierProvider` وشاشة اختيار لغة ([language_bottom_sheet.dart](../../presentation/widgets/common/language_bottom_sheet.md))، لكن **كل** النصوص هنا عربية فقط بدون أي مكافئ إنجليزي ولا استخدام لآلية ترجمة حقيقية (`intl`/ARB files عبر `flutter gen-l10n`, أو حتى Map بسيط `{ar: ..., en: ...}`). أي أن اختيار "English" من إعدادات اللغة (لو نفّذ فعلياً) سيغيّر فقط اتجاه النص (LTR) والودجت المدمجة بفلاتر (مثل date picker)، لكن كل نص من `AppStrings` سيبقى عربياً — تجربة نصف منجزة ومربكة لمستخدم اختار الإنجليزية. **يحتاج تأكيد إضافي:** هل تُستخدم `AppStrings` فعلاً بكل الشاشات أم أن أغلب الشاشات تكتب نصوصاً عربية حرفية inline بدل استيراد هذا الملف؟ (سيتّضح تراكمياً في مراجعة الشاشات — سأجمّع ملاحظة نهائية بـ 99_summary.md).
  - 🟠 **متوسطة — مؤكَّدة فعلياً: `AppStrings.cities` قائمة ناقصة ومتروكة خلف الركب، تُستخدم فعلياً بـ`search_screen.dart`:** تحقّقت بالبحث الشامل بالكود: `AppStrings.cities` (8 مدن + "الكل") **يُستخدَم فعلياً بمكان واحد فقط: [search_screen.dart](../../presentation/screens/search/search_screen.md) سطر 946**. بمقارنته بقائمة المدن الأحدث والأكمل المعرَّفة محلياً بـ[home_tab.dart](../../presentation/screens/home/home_tab.md) (`_chips`, 10 مدن + "الكل" — تحتوي أيضاً **طوباس** و**سلفيت** غير الموجودتين هنا إطلاقاً)، وبتعليق فعلي بنفس home_tab.dart يوثّق أن شاشة إضافة شاليه بالمالك (`owner_add_chalet_screen.dart`) تسمح فعلاً بـ10 مدن: **النتيجة مؤكَّدة أن `AppStrings.cities` قائمة قديمة/ناقصة تسبب نفس العطل الذي وُثِّق ووُصلِح صراحة بـ home_tab.dart، لكنه لا يزال قائماً بشاشة البحث المخصصة**: مالك بمدينة "طوباس" أو "سلفيت" يمكنه إنشاء شاليه فعلياً وسيظهر بالتصفح العام، لكن **لا توجد وسيلة لعميل تصفية نتائج البحث خصيصاً لهاتين المدينتين** من شاشة البحث (`search_screen.dart`) — فقط عبر "الكل"/بدون فلتر. هذا ليس افتراضاً نظرياً بل انحراف بيانات مؤكَّد بمقارنة مباشرة بين ملفين فعليين بنفس المشروع.

  - 🟡 **بسيطة — ربط بالقيمة النصية بدل معرّف مستقر:** `cities` تُقارَن على الأرجح بعمود `chalets.city` النصي مباشرة (`==` على سلسلة عربية). أي اختلاف بسيط بالتشكيل/المسافات/لهجة الكتابة بين هذه القائمة وقيم قاعدة البيانات الفعلية يعني أن فلتر مدينة معيّن يرجّع **صفر نتائج بصمت** دون أي خطأ ظاهر (لا استثناء، فقط قائمة فارغة تبدو وكأنها "لا توجد شاليهات"). نفس الملاحظة تنطبق بشكل عام على أي قائمة مدن مبرمجة يدوياً (hardcoded) بأي ملف آخر بالمشروع.

- **اقتراح الإصلاح:**
  - **إصلاح فوري وسريع:** إضافة "طوباس" و"سلفيت" لقائمة `AppStrings.cities` هنا (لتطابق قائمة `_chips` بـhome_tab.dart وقائمة owner_add_chalet_screen.dart)، حتى تتفعّل تصفية هاتين المدينتين بشاشة البحث فوراً دون انتظار حل جذري.
  - لمشكلة i18n: إما اعتماد `flutter gen-l10n` الرسمي (ARB files لكل لغة) بدل class ثابت أحادي اللغة، أو -كحل أسرع بدون إعادة هيكلة كبيرة- تحويل كل `static const String` إلى دالة `static String x(BuildContext context)` تقرأ من خريطة `{ar: '...', en: '...'}` حسب `Localizations.localeOf(context)`.
  - لمشكلة المدن: الأفضل أن تأتي قائمة المدن من قاعدة البيانات نفسها (مثلاً `SELECT DISTINCT city FROM chalets`) أو Enum/كود مستقر (`city_code`) بدل نص حر مطابَق حرفياً، بحيث لا ينكسر الفلتر بصمت لو تغيّر نص مدينة بقاعدة البيانات.
