### lib/data/services/location_service.dart

- **الوظيفة:** خدمة موقع جغرافي (GPS) صغيرة: طلب الصلاحية، جلب الموقع الحالي بأمان، وحساب المسافة بين نقطتين.

- **الشرح التفصيلي:**
  - `getCurrentPosition()`: يتحقق أولاً `Geolocator.isLocationServiceEnabled()` (GPS مفعّل بالجهاز؟)، ثم `checkPermission()`/`requestPermission()` (يطلب الصلاحية فقط لو `denied`)، يعيد `null` لو `denied` بعد الطلب أو `deniedForever`، وإلا يستدعي `getCurrentPosition(locationSettings: LocationSettings(accuracy: LocationAccuracy.medium))`. الكل ملفوف بـ `try/catch` عام يعيد `null` عند أي خطأ.
  - `distanceInKm`: غلاف بسيط حول `Geolocator.distanceBetween` (يُرجع أمتاراً) مع تحويل للكيلومتر.
  - تعليق توثيقي أعلى الـ class يوضّح صراحة فلسفة التصميم: "لا تفترض شيء عن حالة الصلاحية مسبقاً — تتحقق فعلياً دائماً، وتتعامل بهدوء (ترجع null) عند أي رفض أو خطأ بدل رمي استثناء".

- **الاعتماديات:** يستورد `package:geolocator/geolocator.dart` فقط. **من يستخدمه:** على الأرجح شاشة الخريطة ([palestine_chalets_map_screen.dart](../../presentation/screens/map/palestine_chalets_map_screen.md)) و/أو الرئيسية لفرز "الأقرب لي" — يُؤكَّد عند مراجعتهما.

- **التعامل مع Supabase:** لا يوجد إطلاقاً — خدمة جهاز محلية بحتة (لا علاقة لها بقاعدة البيانات).

- **نقاط القوة:**
  - تعامل دفاعي كامل ومتّسق مع كل احتمالات رفض/تعطيل صلاحية الموقع (لا استثناءات غير متوقعة تصل للمستدعي) — نمط "ترجع null بهدوء" مناسب تماماً لميزة اختيارية (الموقع الجغرافي ليس أساسياً لعمل التطبيق).
  - توثيق فلسفة التصميم بوضوح بتعليق أعلى الـ class، مفيد لأي مطوّر لاحق يتساءل "لماذا ترجع null بدل throw؟".

- **الأخطاء والمخاطر المحتملة:**
  - 🟡 **بسيطة (سطر 28-32):** لا يوجد `timeLimit`/timeout صريح مُمرَّر لـ `Geolocator.getCurrentPosition`. **يحتاج تحقق فعلي** (لم أختبره): على بعض الأجهزة/الأماكن ضعيفة استقبال GPS، هل يمكن أن ينتظر هذا النداء لفترة طويلة جداً دون إشارة زمنية قصوى؟ لو كانت الشاشة المستهلكة تعرض "جاري التحميل" دون حد زمني أقصى مرتبط بهذا النداء تحديداً، قد يبدو التطبيق عالقاً على أجهزة بإشارة GPS ضعيفة.
  - 🟡 **بسيطة:** `catch (_)` بدون أي تسجيل (logging) للخطأ الفعلي (حتى لـ Sentry المُفعَّل أصلاً بـ[main.dart](../../../main.md)) — لو تكرر فشل الموقع الجغرافي بأعداد كبيرة من المستخدمين لسبب برمجي حقيقي (وليس مجرد رفض صلاحية طبيعي)، لا توجد أي وسيلة لرصد ذلك من لوحة Sentry.

- **اقتراح الإصلاح:**
  - إضافة `timeLimit: const Duration(seconds: 10)` (أو ما شابه) لـ `LocationSettings`، والتعامل مع `TimeoutException` كحالة `null` أيضاً — لضمان عدم انتظار غير محدود.
  - تمييز اختياري بين "رفض الصلاحية" (متوقع وطبيعي) و"خطأ فعلي" (`catch (e) { if (e is! PermissionDeniedException) Sentry.captureException(e); return null; }`) لإبقاء رؤية على الأعطال الحقيقية دون إزعاج بتنبيهات كل رفض صلاحية طبيعي.
