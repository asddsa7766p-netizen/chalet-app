### lib/presentation/screens/payment/card_details_screen.dart

- **الوظيفة:** شاشة (3) بتدفق الدفع — إدخال بيانات بطاقة ائتمانية (رقم، اسم حامل، تاريخ انتهاء، CVV) مع تنسيق تلقائي أثناء الكتابة. (راجع [ملاحظة السياق العامة](payment_flow_entry.md)).

- **الشرح التفصيلي:**
  - `_CardNumberFormatter`/`_ExpiryDateFormatter` (`TextInputFormatter` مخصّصان): يضيفان مسافة كل 4 أرقام لرقم البطاقة، و`/` تلقائياً بين شهر/سنة الانتهاء أثناء الكتابة — تنسيق UX جيد ومطبَّق بشكل صحيح تقنياً.
  - تحقق: رقم البطاقة 16 رقماً بالضبط، تاريخ انتهاء بصيغة `MM/YY` عبر regex، CVV 3-4 أرقام — تحقق صيغة أساسي (بدون خوارزمية Luhn checksum، مقبول لتطبيق بمرحلة تطوير/محاكاة).
  - `SwitchListTile` "حفظ البطاقة لاستخدامها لاحقاً... يمكنك حذف البطاقة في أي وقت" — يُبنى `CardPaymentInput(..., saveCardForLater: _saveCard)` ويُمرَّر للأمام فقط، **بلا أي منطق تخزين/حذف فعلي بأي مكان بالكود** (لا جدول Supabase لبطاقات محفوظة، لا خدمة تديرها).
  - `dispose()`: يتخلّص من كل الـ4 controllers بشكل صحيح.

- **الاعتماديات:** `booking_payment_details.dart`, `payment_theme.dart`, `payment_widgets.dart`, `payment_processing_screen.dart`. **من يستخدمه:** `payment_method_screen.dart` (خيار "بطاقة ائتمانية/مدى").

- **التعامل مع Supabase:** لا يوجد — لا حتى محاولة حفظ البطاقة رغم وجود خيار "حفظها" بالواجهة.

- **نقاط القوة:** `TextInputFormatter` مخصّصان مكتوبان بشكل صحيح وآمن، تحقق صيغة معقول لكل الحقول، إدارة موارد نظيفة (`dispose`).

- **الأخطاء والمخاطر المحتملة:**
  - 🟠 **متوسطة (رغم عدم الوصول الحالي) — خيار "حفظ البطاقة" واجهة كاملة بلا أي وظيفة فعلية خلفها:** يعرض نص صريح يعد المستخدم بإمكانية حفظ بطاقته واستخدامها/حذفها لاحقاً، لكن **لا يوجد أي مسار تخزين حقيقي** — لو فُعِّل هذا المسار يوماً كما هو، سيرى المستخدم مفتاحاً يبدو فعّالاً (Switch On/Off) بلا أي أثر فعلي بعد إتمام الدفع (لن تظهر البطاقة "المحفوظة" بأي مكان لاحقاً). نفس فئة "ميزة تبدو تعمل ولا تعمل فعلياً" الموثّقة بعدة أماكن أخرى بالمشروع (خيار العملة بـsettings_screen.dart، بطاقات التواصل بـhelp_support_screen.dart).
  - 🟡 **بسيطة (سطر 9) — نفس استيراد `flutter_material` المزدوج غير الضروري** الموثَّق بمراجعة [payment_review_screen.dart](payment_review_screen.md).
  - 🟡 **بسيطة:** لا فحص Luhn algorithm لرقم البطاقة (يقبل أي 16 رقماً حتى لو غير صالحة رياضياً) — مقبول لمرحلة محاكاة حالية، يستحق إضافته عند ربط بوابة حقيقية لتقليل أخطاء إدخال واضحة قبل إرسالها للبوابة.

- **اقتراح الإصلاح:**
  - إما تنفيذ حفظ البطاقة فعلياً (عبر بوابة الدفع الحقيقية المستقبلية غالباً، وليس Supabase مباشرة لأسباب PCI-DSS)، أو إخفاء/تعطيل الخيار حتى تتوفر بوابة حقيقية تدعمه فعلياً.
  - إزالة الاستيراد المزدوج لـ`flutter/material.dart`.
