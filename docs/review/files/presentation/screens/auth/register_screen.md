### lib/presentation/screens/auth/register_screen.dart

- **الوظيفة:** شاشة إنشاء حساب جديد (اسم، بريد، هاتف، كلمة مرور + تأكيدها، موافقة على الشروط)، بحالة نجاح كاملة الشاشة تتكيّف ديناميكياً حسب الحاجة الفعلية لتأكيد البريد.

- **الشرح التفصيلي:**
  - `_register()`: يتحقق النموذج، ثم **يتحقق من `_acceptedTerms` منفصلاً** (خارج نظام `Form`/`validator` القياسي — عبر `if (!_acceptedTerms) { showSnackBar(...); return; }`) قبل استدعاء `AuthService.instance.signUp(...)`. عند النجاح: `setState(() { _needsEmailConfirmation = response.session == null; _sent = true; })` — تعليق يوثّق أن هذا الفحص الديناميكي (وليس افتراضاً ثابتاً) أصلح مشكلة حقيقية: رسالة "أكّد بريدك" كانت تظهر دائماً حتى عندما يكون تأكيد البريد التلقائي مفعّلاً فعلياً بالمشروع (والمستخدم مسجَّل دخوله فوراً بلا حاجة تأكيد).
  - `_buildTermsCheckbox()`: Checkbox + نص "أوافق على الشروط والأحكام وسياسة الخصوصية"، مع `TapGestureRecognizer` على جزء "الشروط والأحكام" تحديداً.
  - `_buildSuccessState()`: شاشة نجاح كاملة موحّدة الأسلوب مع [forgot_password_screen.dart](forgot_password_screen.md) (بدل `AlertDialog` صغير سابقاً حسب التعليق)، برسالة/أيقونة/زر يتكيّفون حسب `_needsEmailConfirmation`.

- **الاعتماديات:** يستورد [auth_shared.dart](auth_shared.md), `app_colors.dart`, `app_strings.dart`, `services.dart` (`AuthService`). **من يستخدمه:** [app_router.dart](../../../core/router/app_router.md) (مسار `/auth/register`).

- **التعامل مع Supabase:** `AuthService.instance.signUp(email, password, fullName, phone)` فقط.

- **نقاط القوة:**
  - فحص ديناميكي لحاجة تأكيد البريد (`response.session == null`) بدل افتراض ثابت — يتكيّف تلقائياً لو تغيّر إعداد تأكيد البريد بمشروع Supabase مستقبلاً دون الحاجة لتعديل كود.
  - حقل "تأكيد كلمة المرور" مضاف عمداً لتقليل أخطاء الكتابة (موثّق كإضافة واعية، وليس موجوداً أصلاً).
  - Checkbox موافقة على الشروط مُضاف عمداً مع تعليق يوضّح السبب (جمع بيانات شخصية: هاتف/بريد) — وعي بمتطلب قانوني/خصوصية بسيط لكنه حقيقي.
  - رسالة مساعدة استباقية أسفل حقل كلمة المرور ("8 أحرف على الأقل") تقلل احتمال فشل التحقق المفاجئ للمستخدم.

- **الأخطاء والمخاطر المحتملة:**
  - 🟡 **بسيطة (سطر 279-281، مؤكَّدة بقراءة الكود مباشرة) — رابط "الشروط والأحكام" غير وظيفي فعلياً:** `TapGestureRecognizer()..onTap = () { // TODO: افتح شاشة/رابط الشروط والأحكام الفعلي هنا. }` — تعليق TODO حرفي بالكود الحالي. المستخدم يوافق على شروط **لا يستطيع فعلياً قراءتها** بالضغط على الرابط (لا شيء يحدث). فجوة منتج/قانونية حقيقية أكثر منها تقنية، لكنها موجودة فعلاً بالكود المُشغَّل حالياً.
  - 🟡 **بسيطة (سطر 278-282):** إنشاء `TapGestureRecognizer()` مباشرة داخل شجرة `build()` (عبر `_buildTermsCheckbox` المُستدعاة من `build`) بدل تخزينه كحقل بالـ State والتخلص منه صراحة بـ`dispose()` — نمط شائع بفلاتر لكنه من الناحية النظرية يُنشئ recognizer جديداً بكل إعادة بناء بدون `dispose()` صريح للقديم (يُعتمَد على GC العادي؛ ليس تسريباً متراكماً خطيراً لأن لا شيء آخر يحتفظ بمرجع للـ recognizer القديم، لكنه يخالف التوصية الرسمية لفلاتر بالتخلص الصريح من Gesture Recognizers).
  - 🟡 **بسيطة (سطر 44):** `_formKey.currentState!.validate()` — نفس ملاحظة [login_screen.dart](login_screen.md) (استخدام `!` مباشر، خطورة عملية منخفضة جداً).
  - 🟡 **بسيطة:** لا يوجد فحص `mounted` قبل `ScaffoldMessenger.of(context).showSnackBar(...)` بسطر 48 (تحقق شروط) — لكن هذا الاستدعاء **متزامن بالكامل** (لا `await` قبله بنفس المسار)، فلا خطر فعلي هنا؛ أُذكره فقط لأنه ظاهرياً يشبه نمط الخطر لكنه بالفحص الدقيق **ليس** خطراً حقيقياً (لا فجوة async قبله).

- **اقتراح الإصلاح:**
  - ربط `TapGestureRecognizer` بشاشة/رابط الشروط والأحكام الفعلي — **حل جاهز وموجود فعلاً بالمشروع لا يحتاج شاشة جديدة**: [settings_screen.dart](../settings/settings_screen.md) يحتوي بالفعل `_TermsScreen` (كلاس خاص بذلك الملف، بمحتوى نائب صريح لكنه شاشة كاملة وظيفية) يمكن فتحها من هنا مباشرة (`Navigator.push(context, MaterialPageRoute(builder: (_) => const _TermsScreen()))` بعد جعلها public، أو استخراجها لملف مشترك). أولوية أعلى من بقية ملاحظات هذا الملف لأنها فجوة وظيفية حقيقية ولها حل جاهز وموجود، وليست مجرد قلق نظري.
  - (اختياري، تحسين بسيط) تخزين `TapGestureRecognizer` كحقل بالـ State مع `dispose()` صريح، تماشياً مع توصية Flutter الرسمية لإدارة Gesture Recognizers.
