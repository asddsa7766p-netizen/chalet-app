### lib/presentation/screens/home/home_tab.dart

- **الوظيفة:** الشاشة الرئيسية (تبويب "الرئيسية") — هيدر (جرس إشعارات + شعار + اختيار مدينة)، ترحيب شخصي، بحث، بانر ترويجي، فئات سريعة، "أماكن مميزة"، أقسام حسب المدينة، و"بالقرب منك" (حسب GPS). **1297 سطر — ثاني أكبر ملف شاشات بالتطبيق بعد booking_screen.dart، وأكثر ملف موثَّق بتعليقات "✅ إصلاح" بكل المشروع (يُقارِب 12 إصلاحاً موثّقاً بالتفصيل).**

- **الشرح التفصيلي:**
  - **`initState`**: يشغّل بالتوازي `_loadUserLocation()`, `_loadUnreadNotifications()`, `_initCityPreferenceThenLoad()` (التي تحمّل تفضيل المدينة المحفوظ محلياً ثم تستدعي `_load()`).
  - **`_load()`**: `Future.wait([getFeaturedChalets(), getCurrentProfile(), getChalets()])` — تحميل متوازٍ لثلاث بيانات مستقلة. عند الفشل: `debugPrint` (بدون Sentry) + `setState(() => _error = e.toString())`.
  - **`_buildTopHeader`**: جرس إشعارات (يفتح `NotificationsScreen` المُعرَّفة داخل `profile_screen.dart` عبر `Navigator.push` **مباشر، وليس عبر GoRouter** كباقي التطبيق) + شعار + زر مدينة (يفتح `_showCityPicker`).
  - **`_showCityPicker({mandatory})`**: Bottom sheet لاختيار مدينة من `_chips` (11 عنصراً: "الكل" + 10 مدن). في أول فتح للتطبيق بدون تفضيل محفوظ، الشيت **إجباري** (`isDismissible: false, enableDrag: false`) — لو حاول المستخدم الإفلات منه (مثلاً زر رجوع أندرويد) تُعاد فتحه فوراً كحماية إضافية. الاختيار يُحفظ فوراً بـ`SharedPreferences` بمفتاح خاص بكل مستخدم (`preferred_city_<uid أو guest>`) حتى لا يظهر الشيت الإجباري مرة أخرى.
  - **`_buildGreeting`**: يجمع الاسم من `ref.watch(profileProvider)` (الأساسي، تفاعلي) مع سقوط احتياطي لـ`_userName` (المحمَّل مباشرة بـ`_load()`).
  - **`_buildCategoriesRow`/`_buildMostBookedSection`/`_buildCitySection`/`_buildNearYouGrid`**: أقسام تُبنى من `_featured`/`_allForGrouping` (محمَّلة مرة واحدة، تُفلتَر محلياً حسب `_selectedCity` أو GPS دون أي طلب شبكة إضافي).
  - **`_buildPlaceCard`/`_buildNearYouTile`**: بطاقات شاليه قابلة لإعادة الاستخدام، تعرض قلب مفضّلة (`ref.watch(isFavoriteProvider(chalet.id))`) وتنتقل لـ`/home/chalet/:id` مع تمرير `ChaletModel` كاملاً كـ`extra` (يتفادى إعادة تحميل الشاليه بشاشة التفاصيل).

  **إصلاحات موثّقة بالتعليقات (ملخّص — كلها فعلية ومؤكَّدة بقراءة الكود الحالي، وليست وعوداً):**
  1. مربع بحث الرئيسية كان يطلق شبكة بكل ضغطة مفتاح دون عرض أي نتيجة — أصبح يوجّه لـ`SearchScreen` عند الإرسال فقط.
  2. اختيار مدينة كان يطلق إعادة تحميل شبكة كاملة لأثر غير مرئي فعلياً — أصبح فلترة محلية فورية.
  3. زر اختيار المدينة بالهيدر كان `onTap` فارغاً (TODO) — أصبح شيت اختيار كامل مع حفظ تفضيل دائم.
  4. `_userName` كان يُحمَّل بنجاح ولا يُعرض بأي مكان — أصبح يُستخدم بترحيب شخصي.
  5. 3 من 5 فئات سريعة لا تطابق أي فلتر backend حقيقي — أُزيلت لصالح فئتين حقيقيتين فقط (مسبح/واي فاي).
  6. قسما مدينتي "القدس"/"الناصرة" كانا ميتين دائماً (لا شاليه يمكن أن يحملهما) — استُبدلا بمدينتين قابلتين للتحقق فعلياً.
  7. قائمة `_chips` (6 مدن سابقاً) كانت تستثني 4 مدن حقيقية مسموح بها فعلياً بشاشة إضافة الشاليه — **راجع أدناه، هذا الإصلاح لم يُطبَّق بمكان آخر بالمشروع يستخدم قائمة مدن مختلفة**.
  8. جرس الإشعارات كان بلا وظيفة — رُبط بشاشة الإشعارات الفعلية.
  9. `_error` كان يُحسب ولا يُقرأ أبداً — فشل الشبكة يمر بصمت بشاشة فارغة — أصبح يُعرَض فعلياً عبر `_buildError()`.
  10. قسم "أماكن مميزة" كان يُظهر هيكل تحميل (skeleton) للأبد لو لا توجد شاليهات مميزة فعلاً بعد انتهاء التحميل — أصبح يختفي بهدوء.
  11. اختيار مدينة من الهيدر لم يكن يغيّر أي محتوى مرئي بقسم "أماكن مميزة" — أصبح يُفلتَر فعلياً.
  12. "بالقرب منك" تحوّل من عنصر نائب ثابت لحساب مسافة GPS حقيقي.

- **الاعتماديات:** يستورد `chalet_model.dart`, `services.dart`, `location_service.dart`, `notification_service.dart` (⚠️ النسخة المفرد غير المحمية، راجع مراجعتها)، `favorites_provider.dart`, `luxury_widgets.dart`, `profile_screen.dart` (فقط `NotificationsScreen` عبر `show`)، `profile_provider.dart`, `login_prompt.dart`. **من يستخدمه:** [main_screen.dart](../home/main_screen.md) (التبويب الأول بالتنقل السفلي).

- **التعامل مع Supabase:** عبر `ChaletService` (`getFeaturedChalets`, `getChalets` بلا فلتر كأساس للتجميع المحلي)، `AuthService.getCurrentProfile`، `NotificationService.getUnreadCount` (النسخة المفرد بلا try/catch الداخلي، لكن هذا الملف نفسه يلفّها بـtry/catch خاص به بأمان — راجع أدناه).

- **نقاط القوة:**
  - **أكثر ملف بالمشروع يوثّق تاريخ إصلاحات حقيقية بالتفصيل** — كل إصلاح مشروح بـ"ماذا كان يحدث سابقاً ولماذا كان خطأ"، مرجع ممتاز لفهم تطور الشاشة.
  - تحميل متوازٍ (`Future.wait`) بدل متتابع، وفلترة محلية بدل طلبات شبكة متكررة لكل تفاعل مستخدم بسيط (تغيير مدينة).
  - حالات تحميل/خطأ/فارغة مُدارة بعناية فعلية (ليست مجرد ادعاء) — `_loading`, `_error` (مُصلَح ومعروض فعلاً)، وكل قسم يختفي بهدوء (`SizedBox.shrink()`) بدل ترك مساحة فارغة أو هيكل تحميل معلّق.
  - تحميل الموقع/الإشعارات "ثانوية وصامتة عمداً" (fail-silent بتعليق يشرح لماذا) بدون تعطيل باقي الشاشة — قرار تصميم واعٍ لا إهمال.
  - تخزين تفضيل مدينة مقسَّم فعلياً لكل مستخدم/ضيف (`preferred_city_<uid>`) بدل مفتاح عام واحد قد يخلط تفضيلات مستخدمين مختلفين على نفس الجهاز.

- **الأخطاء والمخاطر المحتملة:**
  - 🟠 **متوسطة — مؤكَّدة فعلياً بالمقارنة المباشرة مع ملف آخر: قائمة `_chips` هنا (11 عنصراً، تشمل طوباس وسلفيت) غير متزامنة مع `AppStrings.cities`** (8 مدن فقط بـ[app_strings.dart](../../../core/constants/app_strings.md)) **المستخدمة فعلياً بـ[search_screen.dart](../search/search_screen.md)** — نفس فئة العطل الذي وُثِّق ووُصلِح هنا بالضبط (إصلاح #7 أعلاه) لا يزال قائماً بمكان آخر من التطبيق. تفصيل كامل بمراجعة app_strings.md.
  - 🟡 **بسيطة (سطر 193-202، `_load` catch):** الخطأ يُسجَّل فقط بـ`debugPrint` (غير مرئي بالإنتاج)، لا يُرسَل لـ Sentry رغم تفعيله أصلاً بـ[main.dart](../../../main.md) — فشل تحميل الشاشة الرئيسية (أهم شاشة بالتطبيق) لن يظهر بلوحة مراقبة الأخطاء بالإنتاج.
  - 🟡 **بسيطة (سطر 493-500):** التنقّل لشاشة الإشعارات عبر `Navigator.push`/`MaterialPageRoute` مباشرة بدل `context.go`/`context.push` القياسي (GoRouter) المستخدم بكل بقية الملف والتطبيق — يعني هذا المسار **لا يمر إطلاقاً من حراسة `redirect` المركزية** بـ[app_router.dart](../../../core/router/app_router.md). الأثر الفعلي محدود هنا (الشاشة تتعامل بأمان مع ضيف بلا جلسة — تُرجع قائمة فارغة) لكنه تناقض معماري: تنقّل واحد فقط بكل التطبيق تقريباً لا يمر بالنظام المركزي.
  - 🟡 **بسيطة (سطر 565-569، `_buildGreeting`):** جلب بيانات البروفايل **مرتان مستقلتان** لنفس المستخدم: مرة مباشرة بـ`_load()` (`AuthService.instance.getCurrentProfile()` → `_userName`)، ومرة عبر `ref.watch(profileProvider)` (نفس الدالة داخلياً). ازدواجية شبكة غير ضرورية (ليست خطأ وظيفياً، `_userName` يُستخدم فقط كسقوط احتياطي).
  - 🟡 **بسيطة (سطر 18):** `import 'dart:async' if (dart.library.html) 'dart:async';` — استيراد شرطي يستورد **نفس المكتبة بالضبط** بكلا الفرعين (لا فرق فعلي بين الحالتين) — على الأرجح بقايا نمط conditional-import لم يُكتمل تفعيله الفعلي؛ غير ضار لكنه مربك.
  - 🟡 **بسيطة:** جرس الإشعارات بالهيدر مرئي دائماً حتى للضيف غير المسجّل، ويفتح شاشة ستكون فارغة دائماً بلا أي رسالة توضّح أن تسجيل الدخول يُظهر إشعارات حقيقية.
