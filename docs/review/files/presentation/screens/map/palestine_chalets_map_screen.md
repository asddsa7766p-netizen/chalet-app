### lib/presentation/screens/map/palestine_chalets_map_screen.dart

- **الوظيفة:** خريطة فلسطين (عبر `flutter_map`/OpenStreetMap) تعرض كل الشاليهات المتاحة كعلامات (markers)، مع بطاقة سفلية مختصرة (اسم + سعر + زر "عرض الشاليه") عند الضغط على أي علامة. متاحة للضيف بدون تسجيل دخول.

- **الشرح التفصيلي:**
  - `_load()`: يجلب `ChaletService.instance.getChalets(limit: 1000)` (كل الشاليهات المتاحة/المعتمَدة، بحد أقصى 1000)، ثم يفلتر محلياً: يستبعد أي شاليه بلا إحداثيات، أو بإحداثيات `(0.0, 0.0)` تحديداً (قيمة "جزيرة صفر" الشائعة كإشارة بيانات ناقصة/تالفة)، أو خارج نطاق جغرافي معقول لفلسطين (`lat: 29-34`, `lng: 34-36.5`) — فلترة دفاعية عملية ضد بيانات إحداثيات غير صالحة.
  - `_showChaletBottomSheet`: بطاقة سفلية بسيطة (اسم، سعر، زر إغلاق/عرض) تفتح عند الضغط على أي علامة، تنتقل لـ`/home/chalet/:id` مع تمرير `ChaletModel` كاملاً (يتفادى إعادة تحميل بيانات الشاليه بشاشة التفاصيل — نفس نمط بقية التطبيق).
  - `FlutterMap`: مركز أولي ثابت (`_palestineCenter = LatLng(31.9, 35.2)`، وسط الضفة الغربية تقريباً)، تكبير أولي 9.5، تفاعل محدود بـ`pinchZoom`+`drag` فقط (لا دوران).

- **الاعتماديات:** يستورد `flutter_map`, `latlong2`, `chalet_model.dart`, `services.dart`. **من يستخدمه:** [app_router.dart](../../../core/router/app_router.md) (مسار `/map`، عام/متاح للضيف) و[main_screen.dart](../home/main_screen.md) (تبويب "الخريطة").

- **التعامل مع Supabase:** `ChaletService.instance.getChalets(limit: 1000)` فقط (بدون فلتر مستخدم — نفس الاستعلام العام المتاح للضيف).

- **نقاط القوة:**
  - فلترة دفاعية جيدة ضد إحداثيات تالفة/غير منطقية (`0,0` والنطاق الجغرافي) قبل عرضها على الخريطة — يمنع علامات خاطئة تماماً (وسط المحيط الأطلسي مثلاً) من الظهور.
  - تفاعل خريطة محدود عمداً (لا دوران) — يبسّط تجربة الاستخدام لغرض "استكشاف + اختيار" بدل خريطة ملاحية كاملة غير ضرورية هنا.
  - تمرير `ChaletModel` كاملاً عبر `extra` عند الانتقال لتفاصيل الشاليه — يتفادى نداء شبكة إضافي، متّسق مع بقية التطبيق.

- **الأخطاء والمخاطر المحتملة:**
  - 🟡 **بسيطة (سطر 37، `getChalets(limit: 1000)`):** حد أقصى ثابت (1000) بدل pagination حقيقي أو جلب كل النتائج فعلياً بدون حد. حالياً منخفض الاحتمال عملياً (يستبعد أن يتجاوز عدد الشاليهات المعتمَدة 1000 بالمرحلة الحالية)، لكن لو تجاوز العدد هذا الحد مستقبلاً، ستختفي الشاليهات الأقدم من الخريطة بصمت تامة (لأن `getChalets` تُرتِّب بـ`created_at DESC`) بدون أي مؤشر أن هناك شاليهات إضافية غير معروضة.
  - 🟡 **بسيطة — عدم اتساق مع [chalet_detail_screen.dart](../chalet/chalet_detail_screen.md):** هذه الشاشة تطبّق فحصاً دفاعياً صارماً على الإحداثيات (نطاق جغرافي + استبعاد `0,0`)، بينما `_buildLocationPreview` بشاشة تفاصيل الشاليه تتحقق **فقط** من `lat != null && lng != null` (بدون نفس فحص النطاق/الصفر). شاليه بإحداثيات خاطئة تحديداً بقيمة `(0,0)` سيُستبعَد بصمت من هذه الخريطة العامة، لكنه سيظهر بخريطة مصغّرة خاطئة تماماً (وسط خليج غينيا) بصفحة تفاصيله الخاصة.
  - 🟡 **بسيطة (سطر 191-202) — حالة الخطأ الوحيدة بالتطبيق بلا زر "إعادة المحاولة":** بخلاف كل شاشة أخرى راجعتها حتى الآن بهذا المشروع (الحجز، تفاصيل الشاليه، المفضلة، حجوزاتي، التقييمات — جميعها تعرض زر "إعادة المحاولة" صريحاً عند فشل التحميل)، شاشة الخريطة تعرض نص الخطأ فقط بدون أي وسيلة لإعادة المحاولة سوى مغادرة الشاشة والعودة إليها. كما أن النص نفسه (`'حدث خطأ أثناء تحميل البيانات: $_error'`) يكرّر الرسالة بشكل غير ضروري (لأن `_error` نفسه مُعرَّف مسبقاً كجملة عربية كاملة "تعذر تحميل الخريطة، يرجى المحاولة لاحقاً"، فتُعرض الجملتان مدمجتين بصياغة مكرَّرة قليلاً).
  - 🟡 **بسيطة:** لا استخدام لـ`LocationService` (GPS) هنا رغم استخدامه فعلياً بشاشات أخرى مشابهة ([home_tab.dart](../../home/home_tab.md), [chalet_detail_screen.dart](../chalet/chalet_detail_screen.md)) — الخريطة لا تتمركز حول موقع المستخدم الفعلي ولا تعرض علامة "أنت هنا"، رغم أن هذا سياق طبيعي جداً لميزة كهذه. ليس عطلاً، لكنه فرصة تحسين تجربة مستخدم واضحة غير مُستغَلة، خصوصاً أن البنية التحتية (`LocationService`) جاهزة أصلاً بالمشروع.

- **اقتراح الإصلاح:**
  - إضافة نفس فحص النطاق الجغرافي/استبعاد `(0,0)` المستخدم هنا إلى `_buildLocationPreview` بـ[chalet_detail_screen.dart](../chalet/chalet_detail_screen.md) (أو الأفضل: استخراج دالة تحقق واحدة مشتركة `bool isValidPalestineCoordinate(double? lat, double? lng)` تستخدمها الشاشتان معاً).
  - إضافة زر "إعادة المحاولة" لحالة الخطأ، بنفس نمط بقية شاشات التطبيق، وتبسيط نص الخطأ لعرض `_error` مباشرة بدون بادئة مكرَّرة.
  - (اختياري، تحسين تجربة) استخدام `LocationService.instance.getCurrentPosition()` لتوسيط الخريطة تلقائياً حول موقع المستخدم عند توفره، بدل المركز الثابت دائماً.
